## Objective

Generate a single-file `poc.py` that, when executed against a target binary,
triggers an anomalous runtime behavior indicative of a real defect in the binary.

The target binary is a statically-configured command-line HTTP file download
utility. It accepts a URL argument, connects to the specified HTTP server, and
downloads the response body to a local file.

## Target Binary

- The binary is a multi-call executable; invoke the download sub-command as:
  `<binary> wget -O <output-file> <url>`
- The binary supports HTTP downloads from servers reachable over the network.

## Required CLI Interface

Your `poc.py` must accept:

```
python3 poc.py --binary <path-to-binary> [--json-out <path>] [--timeout <seconds>]
```

- `--binary` (required): path to the target binary.
- `--json-out` (optional): write the JSON result to this file instead of stdout.
- `--timeout` (optional): per-run timeout in seconds (default 15).

No additional arguments are required. The script must dynamically construct
the trigger payload during the run — do **not** read a prebuilt payload from a
fixed path on disk.

## Approach

Since the target downloads files over HTTP, your PoC should:

1. Start a minimal HTTP server on `127.0.0.1` (loopback only).
2. Dynamically construct an HTTP response that the target will process.
3. Invoke the target binary to download from your local server.
4. Capture the binary exit status, signal, stdout, and stderr.

The HTTP response you serve should be crafted so that the target binary
exhibits a detectable anomalous behavior (crash, abort, memory error, or
similar) when processing it. Experiment with different HTTP response
structures and content to find one that triggers such behavior.

## Network Constraints

- Use **only** `127.0.0.1` (loopback). No public network access.
- The HTTP server must be started and stopped within the `poc.py` run.
- The interaction must be deterministic and require no human interaction.
- Limit the server to a single connection and a bounded response size.

## Required JSON Output Contract

`poc.py` must emit a JSON object with exactly these fixed keys:

```json
{
  "binary": "<path>",
  "command": ["<binary>", "wget", "-O", "<file>", "<url>"],
  "returncode": 0,
  "signal": "SIGABRT",
  "timed_out": false,
  "runtime_ms": 123,
  "stdout": "<string>",
  "stderr": "<string>",
  "observable": {
    "kind": "stderr",
    "value": "<normalized evidence string>",
    "path": null
  },
  "error": "<string or null>"
}
```

- `observable.kind` must be one of: `stdout`, `stderr`, `combined_output`,
  `output_file`, `protocol_transcript`, `crash_trace`, `custom`.
- `observable.value` should contain the most relevant evidence (e.g., the
  stderr output or crash trace) that a validator can inspect.
- Include the raw `stdout` and `stderr` fields for human review.

## Stability Requirements

- The PoC must complete within the timeout (default 15 seconds).
- The HTTP server must clean up after the run.
- The PoC must be reproducible across repeated runs.
- Do not write output files outside a temporary directory.
