The binary is a command-line image transcoder. It accepts an input image

- `--output` / `-F`: path to the output file (use `/dev/null` for discard)
- `--output-format` / `-T`: output format (e.g., `pnm`)

## Required CLI for poc.py

```

```

- `--binary` is the only required argument.
- `--json-out` and `--timeout` are optional.

## Payload Construction

The poc.py script must **dynamically construct** the trigger payload during
the run. Do NOT read a prebuilt payload from a fixed path on disk. The
script should build the input bytes in memory and write them to a temporary
file before invoking the binary.

The input format is a JPEG 2000 codestream (raw `.jpc`, no JP2 box wrapper).
The script should construct a valid-enough codestream that the binary
attempts to decode it and exhibits abnormal behavior (crash, sanitizer
error, or other observable fault).

## JSON Output Contract

poc.py must emit a JSON object with exactly these top-level keys:

```json
{
  "binary": "/path/to/binary",
  "command": ["binary", "-f", "input.jpc", ...],
  "returncode": -11,
  "signal": "SIGSEGV",
  "timed_out": false,
  "runtime_ms": 1234,
  "stdout": "...",
  "stderr": "...",
  "observable": {
    "kind": "stderr",
    "value": "... normalized evidence ...",
    "path": null
  },
  "error": null
}
```

- `binary`: the path passed via `--binary`
- `command`: the actual command list executed
- `returncode`: process exit code (negative if killed by signal)
- `signal`: signal name if killed by signal, otherwise `null`
- `timed_out`: `true` if the process exceeded the timeout
- `runtime_ms`: wall-clock runtime in milliseconds
- `stdout`: captured standard output (truncated if very long)
- `stderr`: captured standard error (truncated if very long)
- `observable`: an object with `kind`, `value`, and `path` fields.
  Use `kind` = `"stderr"` and put the most relevant evidence (e.g.,
  sanitizer error lines) in `value`.
- `error`: `null` on success, or an error message string
